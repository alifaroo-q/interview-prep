# AWS primary-source facts: networking, identity, delivery, security, observability

Date checked: 2026-10-07. Sources: docs.aws.amazon.com and aws.amazon.com only.
Format per line: fact | URL | "short exact quote".
Dollar prices are US East (Ohio) examples from the page on the date checked. Prices change.

## 1. VPC

- A VPC IPv4 CIDR block can be /16 to /28. | https://docs.aws.amazon.com/vpc/latest/userguide/vpc-cidr-blocks.html | "The allowed block size is between a `/16` netmask (65,536 IP addresses) and `/28` netmask (16 IP addresses)."
- A subnet IPv4 CIDR block is also /28 to /16. | https://docs.aws.amazon.com/vpc/latest/userguide/subnet-sizing.html | "The allowed IPv4 CIDR block size for a subnet is between a `/28` netmask and `/16` netmask."
- A subnet lives in one Availability Zone. | https://docs.aws.amazon.com/vpc/latest/userguide/configure-subnets.html | "Each subnet must reside entirely within one Availability Zone and cannot span zones."
- 5 IPv4 addresses per subnet are reserved: first four and the last one. | https://docs.aws.amazon.com/vpc/latest/userguide/subnet-sizing.html | "The first four IP addresses and the last IP address in each subnet CIDR block are not available for your use"
- Reserved, for 10.0.0.0/24: .0 network address, .1 VPC router, .2 DNS (base plus two), .3 future use, .255 broadcast. | https://docs.aws.amazon.com/vpc/latest/userguide/subnet-sizing.html | "10.0.0.1: Reserved by AWS for the VPC router."
- Public subnet = route to an internet gateway. Private subnet = no direct route to one. | https://docs.aws.amazon.com/vpc/latest/userguide/configure-subnets.html | "Public subnet – The subnet has a direct route to an internet gateway."
- Private subnet instances need a NAT device for the internet. | https://docs.aws.amazon.com/vpc/latest/userguide/configure-subnets.html | "Resources in a private subnet require a NAT device to access the public internet."
- A VPC can have a secondary CIDR; a local route is added for it. | https://docs.aws.amazon.com/vpc/latest/userguide/vpc-cidr-blocks.html | "the destination is the CIDR block and the target is `local`"
- Route table: the VPC CIDR has a `local` route. Example table shows 10.0.0.0/16 to local. | https://docs.aws.amazon.com/vpc/latest/userguide/route-tables-priority.html | "Any traffic destined for a target within the VPC (`10.0.0.0/16`) is covered by the `local` route, and therefore is routed within the VPC."
- Longest prefix match picks the route. | https://docs.aws.amazon.com/vpc/latest/userguide/route-tables-priority.html | "we direct traffic using the most specific route that matches the traffic. This is known as the longest prefix match."
- Every subnet has a route table; the main route table is the default. | https://docs.aws.amazon.com/vpc/latest/userguide/configure-subnets.html | "Every subnet that you create is automatically associated with the main route table for the VPC."
- Internet gateway: scaled, redundant, no bandwidth limit, no charge. | https://docs.aws.amazon.com/vpc/latest/userguide/VPC_Internet_Gateway.html | "horizontally scaled, redundant, and highly available VPC component that allows communication between your VPC and the internet."
- An IGW also does one-to-one NAT for IPv4; the instance needs a public IPv4 or Elastic IP. | https://docs.aws.amazon.com/vpc/latest/userguide/VPC_Internet_Gateway.html | "The internet gateway logically provides the one-to-one NAT on behalf of your instance"
- NAT gateway lets private instances reach out; outside hosts cannot start connections. | https://docs.aws.amazon.com/vpc/latest/userguide/vpc-nat-gateway.html | "external services can't initiate a connection with those instances."
- A public NAT gateway is created in a public subnet and needs an Elastic IP. | https://docs.aws.amazon.com/vpc/latest/userguide/vpc-nat-gateway.html | "You create a public NAT gateway in a public subnet and must associate an Elastic IP address with the NAT gateway at creation."
- NAT gateway is zonal. Share one across AZs and an AZ failure cuts the others off. | https://docs.aws.amazon.com/vpc/latest/userguide/nat-gateway-basics.html | "Each NAT gateway is created in a specific Availability Zone and implemented with redundancy in that zone."
- NAT gateway bandwidth: 5 Gbps, auto-scales to 100 Gbps. | https://docs.aws.amazon.com/vpc/latest/userguide/nat-gateway-basics.html | "A NAT gateway supports 5 Gbps of bandwidth and automatically scales up to 100 Gbps."
- NAT gateway cost: per hour plus per GB processed. | https://aws.amazon.com/vpc/pricing/ | "Data processing charges apply for each gigabyte processed through the NAT gateway regardless of the traffic's source or destination."
- NAT gateway example rate: $0.045 per GB and $0.045 per hour (US East Ohio). Taken from a page summary, rate not copied verbatim. | https://aws.amazon.com/vpc/pricing/ | "NAT Gateway is charged on an hourly basis."
- Security group is stateful. | https://docs.aws.amazon.com/vpc/latest/userguide/vpc-security-groups.html | "Security groups are stateful."
- Security group return traffic is allowed regardless of rules. | https://docs.aws.amazon.com/vpc/latest/userguide/vpc-security-groups.html | "the response traffic for that request is allowed to reach the instance regardless of the inbound security group rules."
- Security group acts at the resource (instance) level. | https://docs.aws.amazon.com/vpc/latest/userguide/vpc-security-groups.html | "after you associate a security group with an EC2 instance, it controls the inbound and outbound traffic for the instance."
- Security group only has allow rules (traffic not allowed is blocked). | https://docs.aws.amazon.com/vpc/latest/userguide/vpc-security-groups.html | "The only traffic that reaches the instance is the traffic allowed by the security group rules."
- A security group can name another security group in rules (same Region for peered VPCs). | https://docs.aws.amazon.com/vpc/latest/peering/vpc-peering-basics.html | "you can reference a security group from the peer VPC as a source or destination for inbound or outbound rules in your security group."
- Several security groups can be on one resource. | https://docs.aws.amazon.com/vpc/latest/userguide/vpc-security-groups.html | "You can also assign multiple security groups to a single resource."
- Network ACL works at subnet level, allow or deny. | https://docs.aws.amazon.com/vpc/latest/userguide/vpc-network-acls.html | "A network access control list (ACL) allows or denies specific inbound or outbound traffic at the subnet level."
- NACL rules are numbered 1 to 32766 and checked lowest first. | https://docs.aws.amazon.com/vpc/latest/userguide/vpc-network-acls.html | "Each rule has a number from 1 to 32766. We evaluate the rules in order, starting with the lowest numbered rule"
- NACL stops at first match. | https://docs.aws.amazon.com/vpc/latest/userguide/nacl-rules.html | "As soon as a rule matches traffic, it's applied regardless of any higher-numbered rule that might contradict it."
- NACL is stateless. Responses need their own rule (so ephemeral ports matter). | https://docs.aws.amazon.com/vpc/latest/userguide/vpc-network-acls.html | "responses to that traffic are not automatically allowed."
- NAT gateway uses ports 1024 to 65535, so the NACL must allow them. | https://docs.aws.amazon.com/vpc/latest/userguide/nat-gateway-basics.html | "NAT gateways use ports 1024–65535."
- Default NACL allows all; one NACL per subnet. | https://docs.aws.amazon.com/vpc/latest/userguide/configure-subnets.html | "The default network ACL allows all inbound and outbound traffic."
- Gateway endpoints are for S3 and DynamoDB only, no PrivateLink, no extra charge. | https://docs.aws.amazon.com/vpc/latest/privatelink/gateway-endpoints.html | "There is no additional charge for using gateway endpoints."
- Gateway endpoints need no IGW or NAT. | https://docs.aws.amazon.com/vpc/latest/privatelink/gateway-endpoints.html | "Gateway VPC endpoints provide reliable connectivity to Amazon S3 and DynamoDB without requiring an internet gateway or a NAT device for your VPC."
- Gateway endpoint works by a route to a prefix list in the route table. | https://docs.aws.amazon.com/vpc/latest/privatelink/gateway-endpoints.html | "The destination is a prefix list for the service owned by AWS and the target is the gateway endpoint."
- Interface endpoint = PrivateLink; creates an ENI in your subnet. | https://docs.aws.amazon.com/vpc/latest/privatelink/concepts.html | "For each subnet that you specify when you create a VPC endpoint, we create an endpoint network interface in the subnet."
- Interface endpoint sends TCP or UDP; name resolved by DNS. | https://docs.aws.amazon.com/vpc/latest/privatelink/concepts.html | "Create an *interface endpoint* to send TCP or UDP traffic to an endpoint service."
- PrivateLink traffic stays on the AWS network. | https://docs.aws.amazon.com/vpc/latest/privatelink/concepts.html | "Traffic between a VPC endpoint and an endpoint service or resource stays within the AWS network, without traversing the public internet."
- Gateway endpoint does not use PrivateLink. | https://docs.aws.amazon.com/vpc/latest/privatelink/concepts.html | "Gateway endpoints do not use AWS PrivateLink, unlike the other types of VPC endpoints."
- VPC peering: private routing between two VPCs, cross-account and cross-Region allowed. | https://docs.aws.amazon.com/vpc/latest/peering/what-is-vpc-peering.html | "The VPCs can be in different Regions (also known as an inter-Region VPC peering connection)."
- Peering is not transitive. | https://docs.aws.amazon.com/vpc/latest/peering/vpc-peering-basics.html | "VPC peering does not support transitive peering relationships."
- Peering cannot be used as a transit to another VPC's IGW, NAT or VPN. | https://docs.aws.amazon.com/vpc/latest/peering/vpc-peering-basics.html | "If VPC A has an internet gateway, resources in VPC B can't use the internet gateway in VPC A to access the internet."
- Peering needs non-overlapping CIDRs. | https://docs.aws.amazon.com/vpc/latest/peering/vpc-peering-basics.html | "You cannot create a VPC peering connection between VPCs that have matching or overlapping IPv4 or IPv6 CIDR blocks."
- Both sides must add routes for peering. | https://docs.aws.amazon.com/vpc/latest/peering/vpc-peering-basics.html | "the owner of each VPC in the VPC peering connection must manually add a route to one or more of their VPC route tables"
- Transit Gateway is a hub for VPCs and on-premises networks. | https://docs.aws.amazon.com/vpc/latest/tgw/what-is-transit-gateway.html | "AWS Transit Gateway is a network transit hub used to interconnect virtual private clouds (VPCs) and on-premises networks."
- Transit Gateway cost: per attachment hour plus traffic processed. | https://docs.aws.amazon.com/vpc/latest/tgw/what-is-transit-gateway.html | "You are charged hourly for each attachment on a transit gateway, and you are charged for the amount of traffic processed on the transit gateway."
- Peering has no creation charge; cross-AZ and cross-Region data is charged. | https://docs.aws.amazon.com/vpc/latest/peering/what-is-vpc-peering.html | "There is no charge to create a VPC peering connection."
- Default VPC: each Region, /16 CIDR 172.31.0.0/16, a /20 subnet per AZ, IGW attached, route 0.0.0.0/0 to IGW. | https://docs.aws.amazon.com/vpc/latest/userguide/default-vpc-components.html | "Create a VPC with a size `/16` IPv4 CIDR block (`172.31.0.0/16`)."
- Default subnet size /20 in each AZ. | https://docs.aws.amazon.com/vpc/latest/userguide/default-vpc-components.html | "Create a size `/20` default subnet in each Availability Zone."
- Default VPC has public subnets. | https://docs.aws.amazon.com/vpc/latest/userguide/default-vpc.html | "A default VPC comes with a public subnet in each Availability Zone, an internet gateway, and settings to enable DNS resolution."

## 2. IAM

- Principals: IAM user, STS federated user, IAM role, application. | https://docs.aws.amazon.com/IAM/latest/UserGuide/intro-structure.html | "a principal (an IAM user, AWS STS federated user principal, IAM role, or application)"
- Root user signs in with account email and password. | https://docs.aws.amazon.com/IAM/latest/UserGuide/intro-structure.html | "Root user – Your sign in credentials used for authentication are the email address you used to create the AWS account and the password you specified at that time."
- Federated principals come from an identity provider. | https://docs.aws.amazon.com/IAM/latest/UserGuide/intro-structure.html | "Your identity provider authenticates you and passes your credentials to AWS"
- Identity-based policies attach to user, group or role. | https://docs.aws.amazon.com/IAM/latest/UserGuide/access_policies_identity-vs-resource.html | "Identity-based policies are attached to an IAM user, group, or role."
- Resource-based policies attach to a resource (S3, SQS, KMS keys, ...). Inline only. | https://docs.aws.amazon.com/IAM/latest/UserGuide/access_policies_identity-vs-resource.html | "Resource-based policies are attached to a resource."
- Principal is used in resource-based policies, not in identity-based ones. | https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_elements_principal.html | "You cannot use the `Principal` element in an identity-based policy."
- A role trust policy is a resource-based policy. | https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_elements_principal.html | "The IAM resource-based policy type is a role trust policy."
- Policy elements list: Version, Id, Statement, Sid, Effect, Principal, Action, Resource, Condition (and Not* forms). | https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_elements.html | "Version", "Statement", "Effect", "Principal", "Action", "Resource", "Condition" (section titles on the page)
- Version should be 2012-10-17. | https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_elements_version.html | "`2012-10-17`. This is the current version of the policy language, and you should always include a `Version` element"
- Statement is required; it holds one statement or an array. | https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_elements_statement.html | "The `Statement` element is the main element for a policy. This element is required."
- Default is deny. | https://docs.aws.amazon.com/IAM/latest/UserGuide/intro-structure.html | "By default, all requests are denied."
- An explicit allow in identity or resource policy overrides the default. | https://docs.aws.amazon.com/IAM/latest/UserGuide/intro-structure.html | "An explicit allow in any permissions policy (identity-based or resource-based) overrides this default."
- Explicit deny always wins. | https://docs.aws.amazon.com/IAM/latest/UserGuide/intro-structure.html | "An explicit deny in any policy overrides any allows in any policy."
- SCP/RCP, permissions boundary and session policy must all allow. | https://docs.aws.amazon.com/IAM/latest/UserGuide/intro-structure.html | "If one or more of these policy types exists, they must all allow the request."
- Same account: identity and resource policies are a union. | https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_evaluation-logic.html | "The resulting permissions are the union of the permissions of the two types."
- Permissions boundary: intersection with identity policy. | https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_evaluation-logic.html | "the resulting permissions are the intersection of the two categories."
- SCPs grant nothing; they only set a limit. | https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html | "No permissions are granted by SCPs and RCPs."
- Cross-account needs both sides to allow. | https://docs.aws.amazon.com/IAM/latest/UserGuide/access_policies_identity-vs-resource.html | "There must be policies in both accounts that allow the operation, otherwise the request fails."
- Role has a trust policy (who can assume) and a permissions policy (what they can do). | https://docs.aws.amazon.com/STS/latest/APIReference/API_AssumeRole.html | "a role trust policy that specifies *who* can assume the role, and a permissions policy that specifies *what* can be done with the role."
- AssumeRole returns temporary credentials. | https://docs.aws.amazon.com/STS/latest/APIReference/API_AssumeRole.html | "Returns a set of temporary security credentials that you can use to access AWS resources."
- AssumeRole session duration: 900 s up to role max; default 3600 s; role max 1 to 12 hours. | https://docs.aws.amazon.com/STS/latest/APIReference/API_AssumeRole.html | "The value specified can range from 900 seconds (15 minutes) up to the maximum session duration set for the role. The maximum session duration setting can have a value from 1 hour to 12 hours."
- Default is 3600 s. | https://docs.aws.amazon.com/STS/latest/APIReference/API_AssumeRole.html | "By default, the value is set to `3600` seconds."
- Role chaining caps the session at one hour. | https://docs.aws.amazon.com/STS/latest/APIReference/API_AssumeRole.html | "Role chaining limits your AWS CLI or AWS API role session to a maximum of one hour."
- Session policy: result is intersection with role policy. | https://docs.aws.amazon.com/STS/latest/APIReference/API_AssumeRole.html | "The resulting session's permissions are the intersection of the role's identity-based policy and the session policies."
- Instance profile passes a role to EC2. | https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_use_switch-role-ec2_instance-profiles.html | "Use an instance profile to pass an IAM role to an EC2 instance."
- An instance profile holds only one role. | https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_use_switch-role-ec2_instance-profiles.html | "An instance profile can contain only one IAM role, although a role can be included in multiple instance profiles."
- Compute services deliver role credentials to workloads. No long-lived keys needed. | https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html | "AWS delivers the temporary credentials of an IAM role to that compute resource."
- Least privilege. | https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html | "grant only the permissions required to perform a task."
- ARN format. | https://docs.aws.amazon.com/IAM/latest/UserGuide/reference-arns.html | "arn:{{partition}}:{{service}}:{{region}}:{{account-id}}:{{resource-id}}" (page shows placeholders in double braces; real text is arn:partition:service:region:account-id:resource-id)
- ARN example for an IAM user (no Region). | https://docs.aws.amazon.com/IAM/latest/UserGuide/reference-arns.html | "arn:aws:iam::{{123456789012}}:user/{{john}}" (page marks the values as placeholders)
- IAM Access Analyzer: checks public and cross-account access; validates policies; generates least-privilege policies from CloudTrail. | https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html | "IAM Access Analyzer provides more than 100 policy checks and actionable recommendations"
- Access Analyzer generates findings for resources shared outside the zone of trust. | https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html | "IAM Access Analyzer also monitors supported resource types continuously and generates a finding for resources that allow public or cross-account access."
- Root user: do not use it except for tasks that need it. | https://docs.aws.amazon.com/IAM/latest/UserGuide/root-user-best-practices.html | "We strongly recommend you don’t access the AWS account root user unless you have a task that requires root user credentials."
- Root user: use MFA; all account types require it. | https://docs.aws.amazon.com/IAM/latest/UserGuide/root-user-best-practices.html | "All AWS account types (standalone, management, and member accounts) require MFA to be configured for their root user."
- Root user: do not create access keys. | https://docs.aws.amazon.com/IAM/latest/UserGuide/root-user-best-practices.html | "We strongly recommend that you do not create access keys for your root user"

## 3. Elastic Load Balancing

- ELB spreads traffic across targets in one or more AZs, and only routes to healthy targets. | https://docs.aws.amazon.com/elasticloadbalancing/latest/userguide/what-is-load-balancing.html | "It monitors the health of its registered targets, and routes traffic only to the healthy targets."
- Types today: ALB, NLB, GWLB (and Classic, older). | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/introduction.html | "Elastic Load Balancing supports the following load balancers: Application Load Balancers, Network Load Balancers, Gateway Load Balancers, and Classic Load Balancers."
- ALB works at layer 7. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/introduction.html | "An Application Load Balancer functions at the application layer, the seventh layer of the Open Systems Interconnection (OSI) model."
- ALB listener checks connection requests; rules have priority, conditions, actions. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/introduction.html | "Each rule consists of a priority, one or more actions, and one or more conditions."
- ALB rules can match path, host, header, method, query string, source IP. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/introduction.html | "Support for routing based on fields in the request, such as HTTP header conditions and methods, query parameters, and source IP addresses."
- ALB host-based routing. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/introduction.html | "forward requests based on the host field in the HTTP header."
- ALB target types: instance, ip, lambda. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/load-balancer-target-groups.html | "`instance`", "`ip`", "`lambda`" (target type list)
- ALB IP targets cannot be public IPs. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/load-balancer-target-groups.html | "You can't specify publicly routable IP addresses."
- NLB works at layer 4. | https://docs.aws.amazon.com/elasticloadbalancing/latest/network/introduction.html | "A Network Load Balancer functions at the fourth layer of the Open Systems Interconnection (OSI) model."
- NLB target group protocols. | https://docs.aws.amazon.com/elasticloadbalancing/latest/network/introduction.html | "Network Load Balancer target groups support the TCP, UDP, TCP\_UDP, TLS, QUIC, and TCP\_QUIC protocols."
- NLB: millions of requests per second. | https://docs.aws.amazon.com/elasticloadbalancing/latest/network/introduction.html | "It can handle millions of requests per second."
- NLB: static IP per AZ; optional Elastic IP per subnet. | https://docs.aws.amazon.com/elasticloadbalancing/latest/network/introduction.html | "Each load balancer node in the Availability Zone uses this network interface to get a static IP address."
- NLB can keep the client source IP. | https://docs.aws.amazon.com/elasticloadbalancing/latest/network/edit-target-group-attributes.html | "Network Load Balancers can preserve the source IP addresses of clients when routing requests to backend targets."
- NLB client IP preservation defaults: on for instance targets; off for IP targets with TCP/TLS. | https://docs.aws.amazon.com/elasticloadbalancing/latest/network/edit-target-group-attributes.html | "Instance type target groups: Enabled"
- NLB cross-zone is off by default. | https://docs.aws.amazon.com/elasticloadbalancing/latest/network/edit-target-group-attributes.html | "cross-zone load balancing is disabled by default at the load balancer level"
- Gateway Load Balancer works at layer 3, for virtual appliances. | https://docs.aws.amazon.com/elasticloadbalancing/latest/gateway/introduction.html | "A Gateway Load Balancer operates at the third layer of the Open Systems Interconnection (OSI) model, the network layer."
- GWLB uses GENEVE on port 6081. | https://docs.aws.amazon.com/elasticloadbalancing/latest/gateway/introduction.html | "exchange application traffic using the GENEVE protocol on port 6081."
- ALB health check default interval 30 s, timeout 5 s (instance/ip targets). | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/target-group-health-checks.html | "The default is 5 seconds if the target type is `instance` or `ip`"
- ALB health check interval default. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/target-group-health-checks.html | "The default is 30 seconds if the target type is `instance` or `ip`"
- ALB healthy threshold default 5 (range 2 to 10). | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/target-group-health-checks.html | "The range is 2–10. The default is 5."
- ALB unhealthy threshold default 2 (range 2 to 10). | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/target-group-health-checks.html | "The range is 2–10. The default is 2."
- ALB success code default 200. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/target-group-health-checks.html | "The default value is 200."
- ALB health check default path is "/" over HTTP. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/target-group-health-checks.html | "The default is /."
- Fail open when all targets are unhealthy. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/target-group-health-checks.html | "the load balancer fails open."
- Fail open: traffic goes to all targets regardless of health. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/target-group-health-checks.html | "the load balancer routes requests to all those targets, regardless of their health status."
- Deregistration delay default 300 s (range 0 to 3600). | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/edit-target-group-attributes.html | "By default, Elastic Load Balancing waits 300 seconds before completing the deregistration process"
- Deregistering target is in the `draining` state. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/edit-target-group-attributes.html | "The initial state of a deregistering target is `draining`."
- ALB idle timeout default 60 s. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/application-load-balancers.html | "The default is 60 seconds."
- ALB cross-zone always on at load balancer level. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/application-load-balancers.html | "cross-zone load balancing is on by default and cannot be changed at the load balancer level."
- ALB target group can turn cross-zone off. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/edit-target-group-attributes.html | "you can override the default by explicitly turning cross-zone load balancing off at the target group level."
- ALB routing algorithm default round robin; alternatives least outstanding requests, weighted random. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/edit-target-group-attributes.html | "The **round robin** routing algorithm is used by default to route requests at the target group level."
- Least outstanding requests: sends to target with fewest in-progress requests. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/edit-target-group-attributes.html | "routes requests to the targets with the lowest number of in progress requests."
- Sticky sessions use a cookie (AWSALB, duration-based, or app cookie). | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/edit-target-group-attributes.html | "you can use the sticky session feature (also known as session affinity) to enable the load balancer to bind a user's session to a specific target."
- Sticky session duration range 1 s to 7 days. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/edit-target-group-attributes.html | "For **Stickiness duration**, specify a value between 1 second and 7 days."
- ALB can scale; keep a /27 subnet with 8 free IPs per AZ. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/application-load-balancers.html | "at least a `/27` bitmask (for example, `10.0.0.0/27`) and at least eight free IP addresses per subnet."
- ALB needs at least two AZ subnets. | https://docs.aws.amazon.com/elasticloadbalancing/latest/application/application-load-balancers.html | "You must select at least two Availability Zone subnets."

## 4. CloudFront

- Edge locations cache content; request goes to the lowest-latency one. | https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/Introduction.html | "CloudFront delivers your content through a worldwide network of data centers called edge locations."
- Cache miss goes to the origin you define (S3, MediaPackage, HTTP server). | https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/Introduction.html | "If the content is not in that edge location, CloudFront retrieves it from an origin"
